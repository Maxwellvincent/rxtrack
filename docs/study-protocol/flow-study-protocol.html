Flow Study Protocol

Port the vibe-coding flow state into medical study. One lecture → one debug loop.

The mapping

Coding flow triggerMed study equivalent
Run code → instant resultActive recall / practice Q → instant right-or-wrong
Clear binary goalOne closeable objective per block ("answer 20 Q, review misses")
Active buildingMake the card, write the differential, teach it out loud
Bug to solveClinical case / "why is this patient X?"
Difficulty on the edgeBored → integrate/harder; drowning → shrink to one pathway

Per-lecture pipeline

Phase 0 · Ingest (10 min, passive OK)

Turn lecture into raw material

  • Drop lecture (PDF/slides/recording) into inbox-lectures/.
  • pdf2md the deck → markdown. Push to NotebookLM notebook.
  • Skim ONCE for the map — do not try to memorize. Goal = know the shape, not the detail.

Passive is allowed here only. It builds the scaffold the active phases hang on.

Phase 1 · Objectives → binary goals (5 min)

Convert fuzzy topic into closeable tickets

  • Pull the lecture's learning objectives. Each becomes one binary goal.
  • Rewrite as a question, not a topic. "Renal handling of K+" → "Given a drug/acid-base state, predict serum K+ direction and why."
  • Each goal = a ticket you can mark done. Never "study cardio."
Phase 2 · Build the feedback engine (20–30 min, ACTIVE)

Make the cards + questions that give instant feedback

  • Cloze/Anki cards for each objective (NotebookLM → Anki cloze pipeline). Sparing anime mnemonics per your rules.
  • Write 3–5 case stems per lecture — "patient presents with… why?" These are the bugs.
  • Building the card IS learning. This is the active-output requirement.
Phase 3 · Debug loop (timed blocks, DEEP FLOW)

Solve cases + recall, tight loop, no interrupts

  • 25–50 min block. Phone away. One tab. Timer running.
  • Run UWorld/practice Q or your case stems. Answer before revealing.
  • Every miss = error message. Trace the causal chain until you can explain it cold.
  • Blank-page recall the pathway from memory, then check.

This block is where flow lives. Feedback is instant, goal is binary, you are building the explanation.

Phase 4 · Teach + close (10 min)

Prove storage strength

  • Teach the lecture to an imaginary student (or to me) with no notes.
  • Gaps you hit = tomorrow's spaced-review cards.
  • Mark the tickets closed. Log what stuck / what broke → learning-records/.

Difficulty knob (keep the edge)

Bored → integrate 2 systems, harder Q, add time pressure Overwhelmed → shrink to ONE pathway, drop the timer, more scaffold Numb / rereading → STOP. Switch to blank-page recall immediately

Flow-killers to ban

  • Rereading highlighted notes (feels productive, teaches nothing).
  • Open-ended "study this chapter" with no binary goal.
  • Passive rewatching at 2x.
  • Phone / notifications inside a debug block.
