# Mission

## Who
Louis Maxwell — MD candidate. Builds software in flow state easily (vibe coding). Wants
that same "getting lost in it" flow ported to studying medicine.

## Why this matters
Passive med study (reading First Aid, rewatching lectures) kills flow because feedback is
delayed, goals are fuzzy, and the brain is passive. Coding grabs flow because feedback is
instant, goals are binary, and the work is active building. The mission is to make medical
study feel like debugging a case, not absorbing a textbook.

## Definition of success
For each upcoming lecture, Louis runs a repeatable protocol (see `flow-study-protocol.html`)
that converts the lecture into active-recall + case-solving work with tight feedback loops,
and reliably drops into flow while doing it.

## Grounding constraints
- Time-boxed sessions. One binary goal per block.
- Active output every session (recall, card, differential, taught explanation) — never pure input.
- Anki + practice questions are the feedback engine (Louis already builds these pipelines:
  RxTrack, anki dashboards, NotebookLM → Anki).
- Difficulty stays on the edge — bored → harder/integrate; overwhelmed → shrink scope.

## Current mission focus
Run the protocol against real lectures. The lectures are already ingested to markdown and
uploaded into RxTrack, so the work is no longer ingest — it is making each session small enough
to start and finite enough to finish. See `README.md` for where each phase lives in the code.
